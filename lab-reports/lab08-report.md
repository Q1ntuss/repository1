# Звіт з контейнеризації проєкту

## Огляд проєкту
Flask-застосунок реалізує простий веб-сервер, що працює з локальною SQLite базою даних. Він обробляє HTTP-запити, виконує CRUD-операції та забезпечує роботу API/веб-інтерфейсу. Додаток зберігає дані у файлі бази та призначений для легкого розгортання у контейнерах.

## Архітектура контейнерного рішення

### Docker образ
- Базовий образ: python:3.11-slim  
- Розмір фінального образу: ~120–140 MB  
- Використання багатоетапної збірки: ні  

### Docker Compose
- Кількість сервісів: 1 (web)  
- Використовувані volumes:
  - sqlite_data — для збереження файлу бази даних  

## Прийняті рішення та обґрунтування

### Вибір базового образу
Базовий образ `python:3.11-slim` обрано через його компактність, швидкість завантаження та мінімальний набір системних пакетів. Це зменшує розмір образу та пришвидшує деплой, водночас забезпечуючи стабільну роботу Python-застосунку.

### Організація збереження даних
Для збереження SQLite бази створено окрему директорію `/app/data`, яка монтується як volume у Docker Compose. Це забезпечує:
- збереження даних між перезапусками контейнера,
- ізоляцію логіки додатку від даних,
- можливість резервування даних на рівні Docker.

### Оптимізації
- Використання легкого базового образу (`python:3.11-slim`).
- Встановлення залежностей з `--no-cache-dir`.
- Винесення файлу бази даних у volume.
- Створення окремої робочої директорії `/app`.
- Використання змінних середовища для конфігурації.
- Додавання healthcheck для моніторингу працездатності контейнера.

## Інструкції з розгортання
1. Встановити Docker та Docker Compose.
2. За бажанням створити `.env` файл:
   ```
   SECRET_KEY=your-secret-key
   ```
3. Запустити проєкт командою:
   ```
   docker compose up --build -d
   ```
4. Перевірити статус:
   ```
   docker compose ps
   ```
5. Відкрити додаток у браузері:
   ```
   http://localhost:5000
   ```
6. Зупинити контейнер:
   ```
   docker compose down
   ```

## Можливі покращення
- Перейти на багатоетапну збірку для зменшення розміру образу.
- Використати Gunicorn + Nginx для продакшен-середовища.
- Додати автоматичні резервні копії SQLite.
- Додати `.dockerignore`.
- Перенести секрети у Docker secrets або зовнішній менеджер.

## Висновки
Контейнеризація спростила розгортання Flask-додатку, забезпечивши стабільне середовище та зручне управління залежностями. Використання Docker Compose дозволило стандартизувати запуск, а окремий volume — зберегти дані незалежно від життєвого циклу контейнера. Рішення є гнучким, легким для масштабування та модернізації.
