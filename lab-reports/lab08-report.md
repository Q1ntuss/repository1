# Звіт з контейнеризації проєкту

## Огляд проєкту

Цей Flask застосунок надає базовий веб-інтерфейс для взаємодії з даними через SQLite базу. Функціональність включає створення, читання та оновлення записів у базі, а також базовий механізм аутентифікації користувачів.

## Архітектура контейнерного рішення

### Docker образ

- Базовий образ: `python:3.11-slim`
- Розмір фінального образу: ~120 MB (залежить від залежностей)
- Використання багатоетапної збірки: ні (одностадійна збірка)

### Docker Compose

- Кількість сервісів: 1 (`web`)
- Використовувані volumes: `sqlite_data` для збереження бази даних

## Прийняті рішення та обґрунтування

### Вибір базового образу

Обрано `python:3.11-slim` через його легкість і мінімальний розмір, що дозволяє швидко будувати образ та зменшити час деплойменту. Slim-версія включає лише необхідне для запуску Python, що зменшує кількість непотрібних залежностей.

### Організація збереження даних

SQLite база зберігається у volume `sqlite_data`, змонтованому в контейнері за шляхом `/app/data`. Це дозволяє зберігати дані між перезапусками контейнера та забезпечує безпечне і постійне збереження.

### Оптимізації

- Використання `--no-cache-dir` при встановленні залежностей через pip для зменшення розміру образу.
- Організація робочої директорії `/app` та чітка структура копіювання файлів.
- Healthcheck для перевірки доступності сервісу на порті 5000.
- Використання environment variables для конфігурації Flask та шляху до бази даних.


## Можливі покращення

Можливі покращення

Використати багатоступеневу збірку Docker для зменшення розміру образу

Додати підтримку production-середовища з Gunicorn або uWSGI замість Flask run

Налаштувати автоматичне резервне копіювання SQLite бази

Інтегрувати CI/CD для автоматичного збірки та деплойменту контейнера

Додати Nginx або інший reverse proxy для маршрутизації та SSL

Використати environment variables для гнучкої конфігурації середовища

Висновки

Контейнеризація значно спростила розгортання Flask проєкту. Використання Docker Compose дозволяє легко масштабувати сервіс і зберігати дані через volumes. Подальші оптимізації, такі як багатоступенева збірка, використання production-серверів і інтеграція з CI/CD, підвищать продуктивність та надійність проєкту, роблячи його готовим для реального використання.
